## Security — 6 Vulnerabilities (all `typescript:S2819`, CRITICAL)

`postMessage(..., '*')` sends data to any origin. **Sensitive** — the sub-application messages
carry the **Keycloak token + user profile**, so `'*'` is a real cross-origin leak.

| File                                                                         | Line         |
| ---------------------------------------------------------------------------- | ------------ |
| `library/ws-widget/utils/src/lib/services/auth-keycloak.service.ts`          | 219          |
| `library/ws-widget/utils/src/lib/services/subapplication-respond.service.ts` | 81, 122, 216 |
| `project/ws/viewer/src/lib/plugins/html/html.component.ts`                   | 590          |
| `project/ws/viewer/src/lib/plugins/iap/iap.component.ts`                     | 85           |

**Fix approach (needs care — do NOT blind-edit):** replace `'*'` with the actual content-frame
origin. The correct origin must come from the content/player host config, because a wrong origin
silently drops the message and breaks the content player (a load-bearing feature). Options, in
order of safety: (1) derive from a configured content-host origin if one exists; (2) restrict to
`window.location.origin` only where the frame is same-origin; (3) if the frame origin is genuinely
dynamic/unknowable, this is the rare case for a justified _won't-fix_ in SonarCloud. Each of the 6
must be assessed against how its target frame is created.
